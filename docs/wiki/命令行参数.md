# 命令行参数

所有参数均为**可选**：不带参数双击运行即走默认流程（自动查找 GitHub Desktop 目录 + 联网获取最新映射）。

> **参数顺序规则**：`--nopause` 是程序级参数，必须写在子命令（如 `dev`）**之前**。
> 正确：`GitHubDesktop2Chinese.exe --nopause dev --invalidcheck`
> 错误：`GitHubDesktop2Chinese.exe dev --nopause --invalidcheck`

## 通用参数

| 参数 | 说明 |
| --- | --- |
| `-h, --help` | 显示帮助并退出 |
| `-g, --githubdesktoppath <目录>` | 指定 GitHub Desktop 的 js 所在目录。校验：目录必须存在，且目录下必须含 `index.html`（即 `resources\app` 目录），否则报错退出 |
| `-j, --json <路径>` | 指定本地 `localization.json` 路径。校验：必须以 `.json` 结尾；文件不存在时会在指定位置**创建模板文件**并提示退出（可当作生成空映射模板的方法） |
| `-r, --onlyfromremote` | 仅从远程仓库读取映射文件（忽略本地同名文件） |
| `--rollback` | 从 `main.js.bak` / `renderer.js.bak` 还原到汉化前状态后退出 |
| `--nopause` | 结束前不再暂停等待按键（脚本 / 自动化场景）。注意：`minversion` 不满足时**不再询问、直接强制替换**。非交互（管道/重定向）运行时即使不加此参数，输入流结束也会自动跳过暂停，不会挂起 |

## 开发者参数（`dev` 子命令）

| 参数 | 说明 |
| --- | --- |
| `-d, --dev` | 启动时直接进入开发者选项菜单（等同按住 `Shift` 启动） |
| `--mainerrorcheck` | [错误检查模式] 对 `main.js` 逐条排查：边替换边按批次写入，可控制「每替换多少条写入一次」，用于定位写坏程序的那条映射 |
| `--rendererrorcheck` | [错误检查模式] 对 `renderer.js` 逐条排查，机制同上 |
| `--invalidcheck` | [检测失效项] 对映射文件逐条检测在当前 js 中是否还能匹配到（含第三项查找正则），失效计数作为退出码返回 |
| `--noreplaceres` | [资源不替换] 只读检测，不写回任何文件（不影响错误检查模式的写入行为） |
| `--translationfrombak` | 优先从 `.bak` 备份读取 js 内容进行替换（在干净底稿上重跑），建议配合 `--invalidcheck` |
| `--devreplace` | [开发模式替换] 仅替换 `main_dev` / `renderer_dev` 数组中的映射，快速调试新条目（注意：会影响其他条目的匹配结果） |
| `--devsetver` | 指定当前程序版本（仅开发者版本 `0.0.0-Dev` 可用，用于调试 `minversion` 逻辑） |

## 开发者选项菜单（按住 Shift 启动或 `-d`）

启动时按住 `Shift`（Windows 检测物理按键状态）或加 `-d` 参数进入：

```
选择你要修改的功能
0) 跳出.
1) [0/1] main崩溃调试.
2) [0/1] renderer崩溃调试.
3) [0/1] 翻译项失效检测.
4) [0/1] 不替换资源.不干预其他开发者选项.
5) [0/1] 优先从备份文件中汉化(会直接改变资源文件的来源,影响其他选项).
6) [0/1] 仅替换指定映射项，以优化汉化作者替换时间
20) [0/1] 手动指定程序版本仅限于调试   ← 仅 0.0.0-Dev 版本显示
```

- 菜单项与 `dev` 子命令参数一一对应，可组合开启，选 `0` 退出菜单继续主流程；
- 输入非法（非数字）会清空输入缓冲后重新询问；输入流结束（管道运行）时直接退出菜单。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功；或自更新下载完成等待替换 |
| `1` | 主流程失败（目录未找到 / 映射读取或解析失败 / 读写文件失败 / 处理异常已回滚 / 回滚部分失败等） |
| `2` | 命令行参数解析失败（CLI11 异常） |
| `3` | 命令行参数解析失败（未知异常） |
| `1~255` | `--invalidcheck` 模式：失效条目数（超过 255 按 255 返回），`0` 表示全部有效 |

> `--invalidcheck` 的退出码可直接用于脚本判断，例如 PowerShell：`GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak; $LASTEXITCODE`

## 常用示例

```powershell
# 常规汉化（自动查找目录 + 联网获取最新映射）
GitHubDesktop2Chinese.exe

# 指定 GitHub Desktop 目录与本地映射文件
GitHubDesktop2Chinese.exe -g "$env:LOCALAPPDATA\GitHubDesktop\app-<版本>\resources\app" -j .\localization.json

# 仅使用远程映射（忽略本地同名文件）
GitHubDesktop2Chinese.exe -r

# 批量检测失效条目（免交互：--nopause 必须在 dev 之前）
#   --translationfrombak：以干净备份为底稿检测，避免已汉化文本干扰匹配
GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak

# 汉化后主程序无法打开：在干净备份上重跑一遍
GitHubDesktop2Chinese.exe dev --translationfrombak

# 撤销汉化、还原汉化前状态
GitHubDesktop2Chinese.exe --rollback

# 生成一份空的映射模板到当前目录
GitHubDesktop2Chinese.exe -j .\template.json

# 查看内置帮助
GitHubDesktop2Chinese.exe --help
```

## 错误检查模式详解（`--mainerrorcheck` / `--rendererrorcheck`）

用于定位「哪一条映射把 GitHub Desktop 写坏了」：

1. 每替换一条打印 `[文件][out:N]已经替换:查找->替换`；
2. 初始批次为 0，写满即写盘并询问「下次替换多少条后写入」，输入数字控制粒度（输入 1 = 每条一写，逐步逼近坏条目）；
3. 非交互运行（输入流结束）时自动变为「剩余全部替换完一次性写入」，不会死循环；
4. 该模式**会真实写盘**，请配合 `--translationfrombak` 保证底稿干净，排查完记得 `--rollback`。
