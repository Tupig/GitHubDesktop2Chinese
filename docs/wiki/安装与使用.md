# 安装与使用

**简体中文** | [English](#installation-and-usage-english)

本文是 TuPigGHD2Chinese 的完整使用说明。只想「双击就能用」的用户看前两节即可；想了解程序每一步在做什么、以及离线/代理等特殊场景，请继续往后读。

## 1. 下载

前往 [Releases](https://github.com/Tupig/TuPigGHD2Chinese/releases) 页面，按平台选择产物：

| 平台 | 产物文件 | 架构 |
| --- | --- | --- |
| Windows | `TuPigGHD2Chinese.exe` | x64 |
| macOS | `TuPigGHD2Chinese-macos-x64` / `TuPigGHD2Chinese-macos-arm64` | 按机器架构选择（Intel 芯片选 x64，Apple Silicon 选 arm64） |
| Linux | `TuPigGHD2Chinese-linux-x64` | x64 |

> - 仅提供 64 位版本（v1.2.6 起移除 32 位）。
> - 每个发布产物都附带构建溯源证明，可用 `gh attestation verify <文件> --repo Tupig/TuPigGHD2Chinese` 校验来源，详见[安全政策](../../SECURITY.md)。
> - Windows 产物的代码签名流程已内置（SignPath 集成，凭据配置后自动启用）；当前产物未签名，请以上述溯源证明校验来源。

### Windows 运行库要求

程序依赖 **Microsoft Visual C++ 运行库（x64）**。如果双击后一闪而过、或提示缺失 `MSVCP140.dll` / `VCRUNTIME140.dll` / `MSVCP140_ATOMIC_WAIT.dll`，请安装 [VC++ Redistributable 最新版](https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist?view=msvc-170) 的 **x64** 版本（`vc_redist.x64.exe`）。

安装后仍无法运行时，检查程序所在目录是否残留 `MSVCP140.dll`、`VCRUNTIME140.dll` 等旧文件——本地残留的旧版 DLL 会遮蔽系统版本，**如有请删除**。

## 2. 两种运行方式

### 方式一（推荐）：只下载可执行文件

双击 `TuPigGHD2Chinese.exe`（macOS / Linux 在终端中执行对应二进制）。

程序启动后发现同目录没有 `localization.json`，会自动从远程仓库拉取最新映射：

```
https://raw.githubusercontent.com/Tupig/TuPigGHD2Chinese/main/json/localization.json
```

拉取成功后进入汉化主流程。此方式可以始终获得最新翻译。

### 方式二：可执行文件 + 本地映射文件

从仓库下载 [`json/localization.json`](https://github.com/Tupig/TuPigGHD2Chinese/blob/main/json/localization.json)，与可执行文件放在**同一目录**后运行。

程序优先读取本地文件，不再联网拉取映射（但仍会做更新检查等联网请求）。适合：

- 网络环境访问 `raw.githubusercontent.com` 不稳定；
- 想固定使用某一版映射；
- 自己改了映射做实验（配合 `-j` 参数可指定任意路径）。

## 3. 运行流程逐步解读

不带参数运行时，程序按以下顺序执行。理解这个流程有助于判断卡在哪一步：

1. **启动横幅与代理探测**
   - 打印开发者署名与版本号；
   - 依次探测 `HTTPS_PROXY` / `https_proxy` 环境变量，未设置时（仅 Windows）回退到系统 IE 代理设置；
   - 检测到代理时会打印 `检测到已开启代理: <host>:<port>`，后续所有联网请求都会走它。

2. **仓库更新时间提示**（仅当本地没有 `localization.json` 时）
   - 查询 GitHub API 显示仓库最近更新时间，帮助判断映射新旧。

3. **加载器自更新检查**（发布版才有，`0.0.0-Dev` 开发版跳过）
   - 请求 `releases/latest` 比对版本；
   - 发现新版本时询问是否自动更新（**默认 n**），确认后走**浏览器直链**下载（不消耗 API 配额）：
     - 按发布资产声明的 **SHA256 摘要**校验完整性；
     - 支持**断点续传**，中断后重跑会接着下；
   - 下载完成后程序退出，等待替换自身后由用户重新运行。

4. **定位 GitHub Desktop 资源目录**
   - `-g` 参数指定的目录优先（要求目录存在且含 `index.html`）；
   - Windows 下读注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\GitHubDesktop` 的 `DisplayVersion` 与 `InstallLocation`，拼出
     `<安装目录>\app-<版本>\resources\app`；
   - 注册表没有或目录不存在时，退回**交互式输入**：直接把文件夹从资源管理器**拖进窗口**即可（自动处理拖拽产生的引号与空白）；
   - 同时向 GitHub Desktop 官方仓库查询最新正式版，本地版本落后时给出黄色「需更新」提示（预览版 beta 不会被误判为最新版）。

5. **回滚短路**（仅 `--rollback` 时）：见第 5 节。

6. **加载汉化映射**
   - `-r` 指定「仅远程」时强制拉取远程映射；
   - 否则：本地 `localization.json` 存在则读本地，不存在则拉远程；
   - 读取后做**结构校验**：顶层必须是 JSON 对象，`main` / `renderer` 数组必须存在且非空，`select` 数组必须存在。任何一项不满足直接报错退出，**不会**用残缺数据做替换。

7. **显示 `tip` 通知**：映射文件可以通过 `tip` 字段在加载器里显示公告（如新版本注意事项）。

8. **文件自愈与备份**
   - `main.js` / `renderer.js` 缺失但存在 `.bak` 备份时，先从备份**还原**再继续；
   - `.bak` 不存在时创建备份：`main.js → main.js.bak`、`renderer.js → renderer.js.bak`；
   - **备份只在首次汉化时创建**，永远保留「最初未汉化」的原始文件，重复运行不会污染备份。

9. **最低版本校验**
   - 映射文件的 `minversion` 声明了所需最低加载器版本；
   - 加载器版本低于它时提示升级；交互模式下可输入 `f` 强制继续（有风险），`--nopause` 模式下会**跳过询问直接强制替换**——脚本化使用时请保证加载器为最新版。

10. **执行替换**
    - 处理 `main.js`：按 `main` 数组逐条正则替换，随后逐项询问 `select` 中 `replaceFile == "main.js"` 且 `enable` 为 true 的可选项（**默认 y**）；
    - 处理 `renderer.js`：同上（`renderer` 数组 + `select` 中 `renderer.js` 的项）；
    - 替换过程中任何正则异常都会**中止且不写入半成品**，并自动从 `.bak` 恢复原文件；
    - 写回采用**原子写入**：先写临时文件再替换，写入中断不会损坏源文件。

11. **收尾**：展示项目贡献者列表（前 10 名），暂停等待按键（`--nopause` 可跳过）后退出。

## 4. GitHub Desktop 更新之后

GitHub Desktop 通过 Squirrel 自动更新，更新后 `app-<新版本>` 是全新目录，汉化随之失效。处理方式：

1. 打开 GitHub Desktop 确认其可正常运行；即使打不开也无需回滚——新版本目录是干净的，直接进行下一步即可；
2. **重新运行一次本程序**，它会从注册表读到新版本号并汉化新目录；
3. 旧版本目录 `app-<旧版本>` 可在 GitHub Desktop 设置中或手动删除。

建议把 `TuPigGHD2Chinese.exe` 固定到开始屏幕/桌面，每次 GitHub Desktop 升级后顺手跑一次。

## 5. 撤销汉化 / 回滚

```powershell
TuPigGHD2Chinese.exe --rollback
```

- 从 `main.js.bak` / `renderer.js.bak` 还原汉化前的状态，两个文件独立处理，单个备份缺失只影响对应文件并给出警告；
- 回滚**只需要目录和备份文件**，在主流程早期执行——即使映射文件损坏或断网也不会被阻断；
- 想彻底恢复英文原版界面，回滚即可；`.bak` 文件可自行删除。

汉化成功但 GitHub Desktop 打不开（通常是映射条目与该版本不兼容）时的另一种修复：

```powershell
TuPigGHD2Chinese.exe dev --translationfrombak
```

它优先从 `.bak`（干净原文）读取内容重新做替换，相当于「在干净底稿上重跑一遍」，常用于加载器升级修复了替换逻辑之后。

## 6. 代理与网络

程序的全部联网请求（更新检查、映射拉取、版本查询）统一走下面探测到的代理：

1. 环境变量 `HTTPS_PROXY` 或 `https_proxy`，支持以下形式（**必须带端口**，端口范围 1–65535）：
   - `host:port` 或 `http://host:port`（`https://` 前缀同样接受）；
   - `user:pass@host:port`（带认证信息的写法可解析，但当前**不支持代理认证**，认证部分被忽略）；
   - `[IPv6地址]:port`（裸 IPv6 不加方括号会被判为无效）；
   - 解析失败会打印错误提示并继续无代理直连；
2. 未设置时（仅 Windows）读取系统 IE/WinHTTP 代理设置（即「设置 → 网络和 Internet → 代理」中配置的值，支持 `http=host:port;https=host:port` 形式，取第一段）。

macOS / Linux 仅支持环境变量方式。

所有请求均使用 HTTPS 并**校验服务器证书**（Windows 加载系统根证书存储；macOS 用 `/etc/ssl/cert.pem`；Linux 探测系统 CA 包）。请求失败时会输出具体原因；更新下载对瞬时 403 与连接失败有自动重试。

## 7. 离线使用

完全离线时：

1. 在有网环境下载 `TuPigGHD2Chinese.exe` 与 `localization.json`；
2. 放入同一目录运行，映射走本地文件；
3. 更新检查失败只会打 warn，不阻断主流程。

注意：**首次运行仍然推荐联网一次**，以便获取最新映射与加载器修复；`minversion` 校验不过时离线环境无法自动升级加载器，只能手动更换新版 exe。

## 8. 开启 GitHub Desktop 预览版功能

GitHub Desktop 内部用环境变量 `GITHUB_DESKTOP_PREVIEW_FEATURES` 控制预览特性开关：

```cmd
set GITHUB_DESKTOP_PREVIEW_FEATURES=1
```

再用该环境变量启动 GitHub Desktop。也可以在加载器运行到 `select` 询问环节时选择开启（对应映射文件中 `是否强制开启预览版选项对应的功能` 一项，直接改写判断表达式，无需手动设环境变量）。

## 9. macOS / Linux 用户须知

- 汉化映射以 **Windows 版** GitHub Desktop 的文案为基准（含 `&` 访问键等 Windows 专属内容），其他平台**绝大多数条目一致**，个别条目可能不匹配——不匹配的条目会被自动跳过，不会破坏程序。
- 非 Windows 平台无法从注册表探测安装目录，启动后按提示**输入或拖入** GitHub Desktop 的资源目录（即同时包含 `main.js` 与 `renderer.js` 的 `app` 目录，通常位于安装位置的 `resources/app` 下），或用 `-g` 参数指定。
- macOS 提供 **x64 与 arm64 单架构包**（Intel 芯片选 x64，Apple Silicon 选 arm64），均**静态链接 OpenSSL** 并经 strip/LTO 裁剪，无额外运行库依赖。

## 10. 安全性说明

- 程序修改的文件仅限 GitHub Desktop 资源目录下的 `main.js` / `renderer.js`，并保留备份——这是预期功能而非恶意行为；
- 自动更新下载会按发布资产声明的 SHA256 摘要校验，完整性不符不会替换；
- 发布产物附带构建溯源证明（SLSA provenance），可校验：

  ```bash
  gh attestation verify <下载的文件> --repo Tupig/TuPigGHD2Chinese
  ```

- 发现安全漏洞请走[私密漏洞报告](../../SECURITY.md)，不要开公开 Issue。

# Installation and Usage (English)

[简体中文](#安装与使用) | **English**

This is the complete usage guide for TuPigGHD2Chinese. If you just want "double-click and it works", the first two sections are enough; read on to understand what the program does at each step, plus special scenarios such as offline usage and proxies.

## 1. Download

Go to the [Releases](https://github.com/Tupig/TuPigGHD2Chinese/releases) page and pick the artifact for your platform:

| Platform | Artifact file | Architecture |
| --- | --- | --- |
| Windows | `TuPigGHD2Chinese.exe` | x64 |
| macOS | `TuPigGHD2Chinese-macos-x64` / `TuPigGHD2Chinese-macos-arm64` | Choose by machine architecture (x64 for Intel chips, arm64 for Apple Silicon) |
| Linux | `TuPigGHD2Chinese-linux-x64` | x64 |

> - Only 64-bit builds are provided (32-bit was removed in v1.2.6).
> - Every release artifact comes with a build provenance attestation; verify its origin with `gh attestation verify <file> --repo Tupig/TuPigGHD2Chinese` — see the [security policy](../../SECURITY.md).
> - The code-signing flow for the Windows artifact is built in (SignPath integration, activated automatically once credentials are configured); artifacts are currently unsigned — verify their origin with the provenance attestation above.

### Windows runtime requirements

The program depends on the **Microsoft Visual C++ runtime (x64)**. If it flashes and closes on double-click, or reports a missing `MSVCP140.dll` / `VCRUNTIME140.dll` / `MSVCP140_ATOMIC_WAIT.dll`, install the **x64** build (`vc_redist.x64.exe`) of the [latest VC++ Redistributable](https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist?view=msvc-170).

If it still fails to run after installing, check whether the program folder contains leftover files such as `MSVCP140.dll` or `VCRUNTIME140.dll` — locally leftover old DLLs shadow the system copies; **delete them if present**.

## 2. Two Ways to Run It

### Option 1 (recommended): download the executable only

Double-click `TuPigGHD2Chinese.exe` (on macOS / Linux, run the corresponding binary in a terminal).

If the program finds no `localization.json` next to it at startup, it automatically fetches the latest mapping from the remote repository:

```
https://raw.githubusercontent.com/Tupig/TuPigGHD2Chinese/main/json/localization.json
```

Once fetched, it enters the main localization flow. This way you always get the latest translations.

### Option 2: executable + a local mapping file

Download [`json/localization.json`](https://github.com/Tupig/TuPigGHD2Chinese/blob/main/json/localization.json) from the repository, put it in the **same directory** as the executable, then run.

The program reads the local file first and no longer fetches the mapping over the network (it still makes network requests such as update checks). Suitable when:

- your network has unstable access to `raw.githubusercontent.com`;
- you want to pin a specific mapping version;
- you are experimenting with your own edits to the mapping (combine with `-j` to use any path).

## 3. Step-by-Step Walkthrough of the Run

When run without arguments, the program executes in the following order. Understanding this flow helps you tell where it is stuck:

1. **Startup banner and proxy detection**
   - Prints the developer credit and version number;
   - Probes the `HTTPS_PROXY` / `https_proxy` environment variables in turn; if unset (Windows only), falls back to the system IE proxy settings;
   - When a proxy is detected, it prints `检测到已开启代理: <host>:<port>`; all subsequent network requests go through it.

2. **Repository update-time hint** (only when there is no local `localization.json`)
   - Queries the GitHub API to show when the repository was last updated, helping you judge how fresh the mapping is.

3. **Loader self-update check** (release builds only; the `0.0.0-Dev` developer build skips this)
   - Requests `releases/latest` and compares versions;
   - When a new version is found, asks whether to auto-update (**default n**); once confirmed, downloads via a **browser direct link** (no API quota consumed):
     - Integrity is verified against the **SHA256 digest** declared by the release asset;
     - **Resumable download** is supported — rerun after an interruption and it continues;
   - When the download completes, the program exits, waits to be replaced, and the user runs it again.

4. **Locating the GitHub Desktop resource directory**
   - The directory given via `-g` takes precedence (it must exist and contain `index.html`);
   - On Windows, reads `DisplayVersion` and `InstallLocation` from the registry key `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\GitHubDesktop` and joins them into
     `<install dir>\app-<version>\resources\app`;
   - If the registry entry is missing or the directory does not exist, it falls back to **interactive input**: just **drag the folder** from File Explorer into the window (quotes and whitespace introduced by dragging are handled automatically);
   - Meanwhile it queries the official GitHub Desktop repository for the latest stable release and shows a yellow "update available" hint when the local version is behind (beta pre-releases are never mistaken for the latest stable).

5. **Rollback short-circuit** (only with `--rollback`): see Section 5.

6. **Loading the localization mapping**
   - With `-r` ("remote only"), the remote mapping is always fetched;
   - Otherwise: if a local `localization.json` exists, read it; if not, fetch the remote one;
   - After reading, a **structural validation** runs: the top level must be a JSON object, the `main` / `renderer` arrays must exist and be non-empty, and the `select` array must exist. If any check fails, the program errors out immediately and **never** performs replacements with incomplete data.

7. **Showing `tip` notices**: the mapping file can show announcements in the loader via its `tip` field (e.g. notes about a new version).

8. **File self-healing and backups**
   - If `main.js` / `renderer.js` is missing but a `.bak` backup exists, it **restores** from the backup first and continues;
   - If `.bak` does not exist, it creates backups: `main.js → main.js.bak`, `renderer.js → renderer.js.bak`;
   - **Backups are created only on the first localization** and always keep the original, unlocalized files; repeated runs never pollute them.

9. **Minimum-version check**
   - The mapping's `minversion` declares the minimum loader version required;
   - If the loader is older, it prompts for an upgrade; in interactive mode you can type `f` to force it (risky); under `--nopause` it **skips the prompt and forces the replacement** — keep the loader up to date when scripting.

10. **Applying replacements**
    - Processes `main.js`: applies the `main` array's regexes one by one, then asks about each `select` item whose `replaceFile == "main.js"` and `enable` is true (**default y**);
    - Processes `renderer.js` likewise (the `renderer` array + the `renderer.js` items in `select`);
    - Any regex error during replacement **aborts without writing partial output** and automatically restores the original file from `.bak`;
    - Writes use **atomic writes**: a temp file is written first, then swapped in — an interrupted write never corrupts the source file.

11. **Wrap-up**: shows the top 10 project contributors, pauses for a keypress (skippable with `--nopause`), then exits.

## 4. After GitHub Desktop Updates

GitHub Desktop auto-updates via Squirrel; the updated `app-<new version>` is a brand-new directory and the localization is gone. What to do:

1. Open GitHub Desktop and confirm it runs; even if it fails to open there is no need to roll back — the new version directory is clean, just go to the next step;
2. **Run this program once more**; it reads the new version number from the registry and localizes the new directory;
3. The old `app-<old version>` directory can be removed via GitHub Desktop settings or manually.

Consider pinning `TuPigGHD2Chinese.exe` to the Start menu / desktop and running it once after each GitHub Desktop upgrade.

## 5. Undoing the Localization / Rollback

```powershell
TuPigGHD2Chinese.exe --rollback
```

- Restores the pre-localization state from `main.js.bak` / `renderer.js.bak`; the two files are handled independently, and a missing backup only affects its own file with a warning;
- Rollback **only needs the directory and the backup files** and runs early in the flow — a corrupted mapping or no network cannot block it;
- To fully restore the original English interface, a rollback is enough; the `.bak` files can be deleted afterwards.

Another fix when the localization succeeded but GitHub Desktop won't open (usually mapping entries incompatible with that version):

```powershell
TuPigGHD2Chinese.exe dev --translationfrombak
```

It re-runs the replacement reading from `.bak` (the clean original) first — effectively "redoing it on a clean draft" — commonly used after a loader upgrade has fixed replacement logic.

## 6. Proxy and Networking

All network requests of the program (update checks, mapping fetches, version queries) go through the proxy detected below:

1. The `HTTPS_PROXY` or `https_proxy` environment variable, in any of these forms (**a port is mandatory**, range 1–65535):
   - `host:port` or `http://host:port` (an `https://` prefix is accepted too);
   - `user:pass@host:port` (the authenticated form parses, but **proxy authentication is not supported** yet — the credential part is ignored);
   - `[IPv6 address]:port` (a bare IPv6 address without brackets is treated as invalid);
   - On a parse failure an error is printed and it continues with a direct connection;
2. If unset (Windows only), the system IE/WinHTTP proxy settings are read (the value configured under "Settings → Network & Internet → Proxy"; the `http=host:port;https=host:port` form is supported, first segment wins).

macOS / Linux only support the environment-variable form.

All requests use HTTPS and **verify server certificates** (Windows loads the system root certificate store; macOS uses `/etc/ssl/cert.pem`; Linux probes the system CA bundle). Failures print the specific reason; update downloads retry automatically on transient 403s and connection failures.

## 7. Offline Usage

Fully offline:

1. Download `TuPigGHD2Chinese.exe` and `localization.json` on a machine with network access;
2. Put them in the same directory and run — the mapping comes from the local file;
3. A failed update check only logs a warning and never blocks the main flow.

Note: **the first run is still best done online once**, to pick up the latest mapping and loader fixes; if the `minversion` check fails offline, the loader cannot auto-upgrade — you must swap in the new exe manually.

## 8. Enabling GitHub Desktop Preview Features

GitHub Desktop controls its preview feature switches with the `GITHUB_DESKTOP_PREVIEW_FEATURES` environment variable:

```cmd
set GITHUB_DESKTOP_PREVIEW_FEATURES=1
```

Then start GitHub Desktop with that variable set. Alternatively, enable it when the loader reaches the `select` prompt (the `是否强制开启预览版选项对应的功能` item in the mapping file, which rewrites the conditional expression directly — no need to set the variable manually).

## 9. Notes for macOS / Linux Users

- The mapping is based on the **Windows** build of GitHub Desktop (including Windows-specific content such as `&` access keys); on other platforms the **vast majority of entries are identical**, with a few possibly not matching — unmatched entries are skipped automatically and never break the program.
- Non-Windows platforms cannot detect the install directory from the registry; follow the prompt to **type in or drag** GitHub Desktop's resource directory (the `app` directory containing both `main.js` and `renderer.js`, usually under `resources/app` in the install location), or specify it with `-g`.
- macOS ships **single-architecture x64 and arm64 packages** (x64 for Intel chips, arm64 for Apple Silicon), both **statically linking OpenSSL** and trimmed with strip/LTO — no extra runtime dependencies.

## 10. Security Notes

- The only files the program modifies are `main.js` / `renderer.js` inside GitHub Desktop's resource directory, and it keeps backups — this is the intended feature, not malicious behavior;
- Self-update downloads verify against the SHA256 digest declared by the release asset; a mismatch is never swapped in;
- Release artifacts carry build provenance attestations (SLSA provenance) that can be verified with:

  ```bash
  gh attestation verify <downloaded file> --repo Tupig/TuPigGHD2Chinese
  ```

- To report a security vulnerability, use [private vulnerability reporting](../../SECURITY.md) — do not open a public Issue.
