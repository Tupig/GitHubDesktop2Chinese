# 常见问题（FAQ / 故障排查）

**简体中文** | [English](#faq--troubleshooting-english)

按症状索引。找不到对应条目时欢迎提 [Issue](https://github.com/Tupig/GitHubDesktop2Chinese/issues)。

## 程序本身无法运行

### 双击后一闪而过 / 提示缺失 `MSVCP140_ATOMIC_WAIT.dll` / `MSVCP140.dll` / `VCRUNTIME140.dll`

安装 [Microsoft Visual C++ Redistributable](https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist?view=msvc-170) 的 **x64** 版本（`vc_redist.x64.exe`）。

安装后仍无法运行：检查程序目录下是否残留 `MSVCP140.dll`、`VCRUNTIME140.dll` 等文件——本地残留的旧版 DLL 会遮蔽系统版本，**如有请删除**。

### 提示找不到 openssl 的 DLL

旧版加载器动态链接 OpenSSL 导致。**更新到 [最新版本](https://github.com/Tupig/GitHubDesktop2Chinese/releases)** 即可，新版已静态链接。

### 中文系统下启动崩溃 / 中文路径报错

v1.2.11 已修复（命令行改用宽字符入口）。请更新到最新版；仍复现请带系统版本与路径示例提 Issue。

### 关闭窗口时弹出提示框

正常行为：汉化中途关闭窗口会导致汉化失败，程序在窗口关闭事件上做了二次确认提示。按流程走完（程序显示「按任意键继续」是**继续**的意思，不是已完成的意思），汉化完成后程序自动退出。

## 找不到 GitHub Desktop

### 提示「注册表中未发现 GitHubDesktop 相关条目」

可能未安装 GitHub Desktop，先[安装](https://desktop.github.com/)并至少启动一次；或者使用便携/非常规安装方式。此时程序会转入手动输入模式——**把 GitHub Desktop 的 `resources\app` 文件夹直接拖进程序窗口**即可（要求目录内含 `main.js` 与 `renderer.js`），或用 `-g` 参数指定：

```powershell
GitHubDesktop2Chinese.exe -g "$env:LOCALAPPDATA\GitHubDesktop\app-<版本>\resources\app"
```

### 提示目录无效 / 该目录下应该是存放 main.js 和 renderer.js 文件的

`-g` 指定的目录不对。正确目录的特征：同时含 `index.html`、`main.js`、`renderer.js`（Windows 默认在 `%LOCALAPPDATA%\GitHubDesktop\app-<版本>\resources\app`）。

### macOS / Linux 上提示「非 Windows 平台无法自动探测 GitHub Desktop 安装目录」

预期行为。手动输入或 `-g` 指定 GitHub Desktop 安装位置下**同时包含 `main.js` 与 `renderer.js`** 的 `resources/app` 目录。

## 汉化过程问题

### 远程获取失败 / 卡在拉取映射

- 程序访问 `raw.githubusercontent.com` 与 `api.github.com`，国内网络可能不通；
- 配置代理：设置环境变量 `HTTPS_PROXY=http://127.0.0.1:7890`（改为你的代理地址，必须带端口），或使用 Windows 系统代理设置——程序会自动探测；
- 或改用[方式二](安装与使用.md#2-两种运行方式)：手动下载 `localization.json` 与 exe 同目录运行。

### 提示「文件要求加载器版本至少为 x.y.z，但加载器版本为 …」

当前加载器太旧，映射用了新加载器才支持的特性。请到 [Releases](https://github.com/Tupig/GitHubDesktop2Chinese/releases) 更新加载器。交互模式下输入 `f` 可强制替换，但**有写坏 GitHub Desktop 的风险**，不建议。

### select 询问环节（如「是否强制开启预览版选项对应的功能」）选错了

重新运行程序即可，每个可选项都会再次询问（直接回车默认 y）。

## 汉化之后的问题

### 汉化后 GitHub Desktop 打不开 / 白屏

映射条目与当前 GitHub Desktop 版本不兼容导致 js 语法被破坏。按顺序尝试：

```powershell
# 1) 更新加载器到最新版（ Releases 页 ）

# 2) 在干净备份上用新版加载器重跑一遍
GitHubDesktop2Chinese.exe dev --translationfrombak

# 3) 仍然打不开 → 回滚还原英文原版
GitHubDesktop2Chinese.exe --rollback
```

回滚后请提 Issue 附上 GitHub Desktop 版本号，便于维护者修复映射。

### 想撤销汉化、恢复英文界面

```powershell
GitHubDesktop2Chinese.exe --rollback
```

从 `main.js.bak` / `renderer.js.bak` 还原汉化前状态。`.bak` 是首次汉化时创建的原始文件，之后可手动删除。

### 界面只汉化了一部分 / 有些还是英文

- GitHub Desktop 更新带来新文案，映射还没覆盖——等维护者补充，或参考[贡献指南](贡献指南.md)自己动手（自动维护工具会生成草稿，补个翻译即可）；
- macOS / Linux 上个别 Windows 专属条目（如 `&` 访问键）不匹配属预期。

### GitHub Desktop 自动更新后界面变回英文

预期行为：更新产生全新 `app-<新版本>` 目录。**重新运行一次本程序**即可。

### 汉化运行到一半强制关闭了，会损坏文件吗

- 写入采用**原子写入**：写中断不会损坏源文件；
- 若正则处理阶段异常，程序会自动从 `.bak` 恢复，不写半成品；
- 不放心可先 `--rollback` 再重新汉化。

## 脚本 / 自动化使用

### 管道或重定向运行时卡住 / 死循环

加 `--nopause` 免交互；v1.2.12 起所有交互点在输入流结束时会自动退出，不再死循环。

注意 `--nopause` 是**程序级参数**，必须写在 `dev` 等子命令**之前**：

```powershell
GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak
```

同时注意：`--nopause` 下 `minversion` 不满足时**不再询问、直接强制替换**，自动化环境请保持加载器为最新版。

### 如何在脚本里判断失效条目数量

`--invalidcheck` 的退出码即失效条数（上限 255），`0` 表示全部有效：

```powershell
GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak
if ($LASTEXITCODE -ne 0) { Write-Host "发现 $LASTEXITCODE 条失效映射" }
```

## 其他

### 是否支持 macOS / Linux？

支持。Release 页提供 macOS x64 / arm64 单架构包与 Linux x64 版本。汉化映射针对 **Windows 版** GitHub Desktop 的界面文案（含 `&` 访问键等 Windows 专属内容），其他平台个别条目可能不匹配（不匹配会被跳过，无副作用）。

### 程序会修改哪些文件？

仅修改 GitHub Desktop 资源目录下的 `main.js` / `renderer.js`，并创建同名 `.bak` 备份。不会触碰仓库、配置与凭据。详见[安全政策](../../SECURITY.md)。

### 如何校验下载产物的来源？

每个发布产物附带构建溯源证明：

```bash
gh attestation verify <下载的文件> --repo Tupig/GitHubDesktop2Chinese
```

### 报告安全漏洞

请走[私密漏洞报告](https://github.com/Tupig/GitHubDesktop2Chinese/security/advisories/new)，不要开公开 Issue。

# FAQ / Troubleshooting (English)

[简体中文](#常见问题faq--故障排查) | **English**

Indexed by symptom. If your issue is not listed, feel free to open an [Issue](https://github.com/Tupig/GitHubDesktop2Chinese/issues).

## The Program Itself Won't Run

### Flashes and closes on double-click / reports missing `MSVCP140_ATOMIC_WAIT.dll` / `MSVCP140.dll` / `VCRUNTIME140.dll`

Install the **x64** build (`vc_redist.x64.exe`) of the [Microsoft Visual C++ Redistributable](https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist?view=msvc-170).

If it still won't run after installing: check whether the program folder contains leftover `MSVCP140.dll`, `VCRUNTIME140.dll` or similar files — locally leftover old DLLs shadow the system copies; **delete them if present**.

### Reports a missing openssl DLL

Caused by older loaders dynamically linking OpenSSL. **Update to the [latest version](https://github.com/Tupig/GitHubDesktop2Chinese/releases)** — the new builds are statically linked.

### Crashes at startup on a Chinese-language system / errors on Chinese paths

Fixed in v1.2.11 (the command line now uses a wide-character entry point). Please update to the latest version; if it still reproduces, open an Issue with your OS version and an example path.

### A confirmation dialog pops up when closing the window

Expected behavior: closing the window mid-localization would abort it, so the program confirms again on the window-close event. Follow the flow to the end (when the program says "press any key to continue", it means **continue** — not that it has finished); the program exits by itself after the localization completes.

## GitHub Desktop Cannot Be Found

### Reports "No GitHubDesktop entry found in the registry"

GitHub Desktop may not be installed — [install](https://desktop.github.com/) it and launch it at least once; or you may be using a portable/non-standard installation. In that case the program switches to manual-input mode — **just drag GitHub Desktop's `resources\app` folder into the program window** (the directory must contain `main.js` and `renderer.js`), or specify it with `-g`:

```powershell
GitHubDesktop2Chinese.exe -g "$env:LOCALAPPDATA\GitHubDesktop\app-<version>\resources\app"
```

### Reports an invalid directory / "this directory should contain main.js and renderer.js"

The directory passed to `-g` is wrong. A correct directory contains `index.html`, `main.js` and `renderer.js` at the same time (on Windows, by default `%LOCALAPPDATA%\GitHubDesktop\app-<version>\resources\app`).

### On macOS / Linux: "cannot auto-detect the GitHub Desktop installation directory on non-Windows platforms"

Expected behavior. Type in, or pass via `-g`, the `resources/app` directory under the GitHub Desktop installation location that **contains both `main.js` and `renderer.js`**.

## Problems During Localization

### Remote fetch fails / stuck while pulling the mapping

- The program accesses `raw.githubusercontent.com` and `api.github.com`, which may be unreachable in some networks;
- Configure a proxy: set the environment variable `HTTPS_PROXY=http://127.0.0.1:7890` (replace with your proxy address; a port is mandatory), or use the Windows system proxy settings — the program detects them automatically;
- Or switch to [Option 2](安装与使用.md#2-两种运行方式): manually download `localization.json`, put it next to the exe and run.

### Reports "the file requires loader version at least x.y.z, but the loader version is …"

Your loader is too old; the mapping uses features only a newer loader supports. Update the loader from [Releases](https://github.com/Tupig/GitHubDesktop2Chinese/releases). In interactive mode you can type `f` to force the replacement, but this **risks breaking GitHub Desktop** — not recommended.

### Answered a select prompt wrong (e.g. "force-enable preview features")

Just run the program again — every optional item is asked about again (pressing Enter directly defaults to y).

## Problems After Localization

### GitHub Desktop won't open / shows a blank screen after localization

Mapping entries are incompatible with the current GitHub Desktop version and broke the js syntax. Try in order:

```powershell
# 1) Update the loader to the latest version ( Releases page )

# 2) Redo on the clean backup with the new loader
GitHubDesktop2Chinese.exe dev --translationfrombak

# 3) Still broken → roll back to the original English version
GitHubDesktop2Chinese.exe --rollback
```

After rolling back, please open an Issue with your GitHub Desktop version so the maintainers can fix the mapping.

### Want to undo the localization and restore the English interface

```powershell
GitHubDesktop2Chinese.exe --rollback
```

Restores the pre-localization state from `main.js.bak` / `renderer.js.bak`. The `.bak` files are the originals created on the first localization and can be deleted afterwards.

### Only part of the interface is localized / some texts are still English

- A GitHub Desktop update introduced new texts not yet covered by the mapping — wait for the maintainers, or do it yourself following the [contribution guide](贡献指南.md) (the auto-maintain tool generates drafts; you just fill in the translation);
- On macOS / Linux, a few Windows-specific entries (such as `&` access keys) not matching is expected.

### The interface turned back to English after GitHub Desktop auto-updated

Expected behavior: the update produces a brand-new `app-<new version>` directory. **Run this program once more**.

### The program was force-closed mid-localization — will files be corrupted?

- Writes use **atomic writes**: an interrupted write never corrupts the source files;
- If an exception occurs during the regex phase, the program automatically restores from `.bak` and never writes half-finished files;
- If unsure, run `--rollback` first and localize again.

## Scripting / Automation

### Hangs or loops forever when run through a pipe or redirection

Add `--nopause` for non-interactive use; since v1.2.12 every interaction point exits automatically when the input stream ends — no more infinite loops.

Note that `--nopause` is a **program-level flag** and must come **before** subcommands such as `dev`:

```powershell
GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak
```

Also note: under `--nopause`, an unsatisfied `minversion` **no longer asks and forces the replacement** — keep the loader up to date in automated environments.

### How to check the number of invalid entries in a script

The `--invalidcheck` exit code is the invalid-entry count (capped at 255); `0` means all valid:

```powershell
GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak
if ($LASTEXITCODE -ne 0) { Write-Host "发现 $LASTEXITCODE 条失效映射" }
```

## Others

### Is macOS / Linux supported?

Yes. The Release page ships single-architecture macOS x64 / arm64 packages and a Linux x64 build. The mapping targets the interface texts of the **Windows** build of GitHub Desktop (including Windows-specific content such as `&` access keys); on other platforms a few entries may not match (unmatched entries are skipped, with no side effects).

### Which files does the program modify?

Only `main.js` / `renderer.js` under GitHub Desktop's resource directory, plus same-named `.bak` backups it creates. It never touches repositories, configuration or credentials. See the [security policy](../../SECURITY.md).

### How do I verify the origin of downloaded artifacts?

Every release artifact carries a build provenance attestation:

```bash
gh attestation verify <downloaded file> --repo Tupig/GitHubDesktop2Chinese
```

### Reporting a security vulnerability

Please use [private vulnerability reporting](https://github.com/Tupig/GitHubDesktop2Chinese/security/advisories/new) — do not open a public Issue.
