# 映射文件格式（localization.json）

**简体中文** | [English](#mapping-file-format-localizationjson-english)

`json/localization.json` 是项目的**核心数据**：英文原文 → 中文译文的映射表。加载器读它执行替换，自动维护工具检测它，CI 校验它。

> 路径 `json/localization.json` 是已发布程序的公共契约（远程拉取 URL 固定指向它），**不可移动**。

## 顶层结构

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `version` | int | 建议 | JSON 文件格式版本（当前 `3`），仅格式变更时递增 |
| `minversion` | string | 建议 | 需要的最低加载器版本（如 `"1.0.0"`）。加载器低于它时提示升级/询问强制执行；解析失败会直接中止 |
| `tip` | string[] | 否 | 加载器启动时显示的公告信息，逐条打印 |
| `select` | object[] | 是 | 本地化时提示用户**选择性**修改的条目 |
| `main` | array | 是 | 用于替换 `main.js` 的映射（非空） |
| `main_dev` | array | 否 | `main.js` 开发调试用快速替换映射（`--devreplace` 时使用） |
| `renderer` | array | 是 | 用于替换 `renderer.js` 的映射（非空） |
| `renderer_dev` | array | 否 | `renderer.js` 开发调试用快速替换映射 |

结构校验失败的后果：`main` / `renderer` 缺失或为空、`select` 缺失 → 加载器**直接报错退出**，不会用残缺数据替换。

## 映射条目格式

`main` / `renderer` / `main_dev` / `renderer_dev` 的每个元素是字符串数组，**二元素**或**三元素**：

```json
["查找正则", "替换文本"]
["查找正则", "替换文本", "全局查找正则"]
```

| 元素 | 角色 | 说明 |
| --- | --- | --- |
| `[0]` | 查找正则 | 按 `std::regex`（ECMAScript 语法）编译，对全文 `regex_replace`。空串或 `"\"\""` 会被跳过 |
| `[1]` | 替换文本 | 作为 `regex_replace` 的 format 串：`$1`…`$9` 引用 `[0]` 的捕获组；`#{n}` 占位符由第三项回填（见下）。反斜杠是**字面量**，不要为正则转义而加 |
| `[2]`（可选） | 全局查找正则 | 先在全文中找**首个**匹配，把其捕获组回填到 `[1]` 的 `#{1}`、`#{2}`… 占位符，再执行主替换 |

### `#{n}` 占位符回填机制

用于「译文需要嵌入 js 运行期才知道的动态文本」的场景。执行顺序：

1. 用 `[2]` 在全文 `regex_search`，取**首个**匹配；
2. 第 i 个捕获组的文本替换 `[1]` 中所有 `#{i}`（回填值中的 `$` 会先转义，防止 format 串意外展开）；
3. 若 `[1]` 中**残留**未回填的 `#{数字}` → 整条**跳过**（写入未回填的占位符会破坏 js 语法）；
4. `[2]` 在全文匹配不到 → 整条跳过并告警；
5. 回填完成后，用 `[0]` 执行常规替换。

### 简单示例

```json
["&File", "文件(&F)"],
["New &repository…", "新建存储库(&R)"]
```

```json
["&View\"", "视图(&V)\""]
```

> 查找项刻意带上结尾引号，避免误匹配 `&View on GitHub` 这类更长文本。

### 带捕获组的示例（`$1`）

js 打包后的变量名（如 `yD`）常因版本更新而变，用 `..` 模糊匹配：

```json
["Ee\\.createElement\\((..),null,this.props.repositoryName",
 "Ee.createElement($1,null,this.props.repositoryName"]
```

- JSON 里 `\\(` → 实际正则 `\(` → 匹配字面量 `(`；
- 替换文本按**字面量**插入：`$1` 引用查找正则的第一个捕获组；**替换文本里绝不能出现 `\\(`**——那是字面反斜杠，会把 `createElement\(` 写进 js 直接语法报错。

### 三元素示例（`#{n}`）

`select` 中现成的一例（强制开启预览版功能）：

```json
["===process\\.env\\.GITHUB_DESKTOP_PREVIEW_FEATURES\\}",
 "===/*process.env.GITHUB_DESKTOP_PREVIEW_FEATURES*/\"1\"}"]
```

## select 数组元素结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `replaceFile` | string | 目标文件，**精确等于** `main.js` 或 `renderer.js`（其他取值整条不生效） |
| `tooltip` | string | 运行时展示给用户的提示信息 |
| `enable` | bool | 此条是否启用 |
| `replace` | string[][] | 二维替换数组，每行格式与主数组条目一致：`[查找正则, 替换文本, 可选查找正则]` |

运行时行为：`enable: true` 的条目会打印 `tooltip` 并询问用户（**默认 y**），确认后执行其所有替换行。典型用途：预览版功能开启、实验性翻译。

```json
{
    "replaceFile": "renderer.js",
    "tooltip": "是否强制开启预览版选项对应的功能",
    "enable": false,
    "replace": [
        ["===process\\.env\\.GITHUB_DESKTOP_PREVIEW_FEATURES\\}",
         "===/*process.env.GITHUB_DESKTOP_PREVIEW_FEATURES*/\"1\"}"]
    ]
}
```

## 条目顺序规则（重要）

查找正则**逐条从头替换，先匹配者生效**——前面的条目改写文本后，后面的条目在改写结果上匹配。因此：

- 新条目一般**追加到末尾**；
- 若新条目与已有条目「**短含长**」（查找项是另一条的子串，如 `"Save"` 与 `"Save":"Add"`），必须把更具体（更长）的条目**插到更宽泛（更短）条目之前**，否则宽泛条目先命中、专条永远失效；
- CI 的 JSON 质量校验会对「短含长」排序错误告警。

## 译文风格约定

CI 质量门会检查（不通过则阻断发布）：

- 问句句末问号统一使用**全角** `？`；
- 译文**末尾不留**多余空格；
- 正则语法必须在 `std::regex` 可编译（黑名单见[正则表达式指南](正则表达式指南.md)）；
- 占位符 `#{n}` 与捕获组 `$n` 使用合法；
- 数组最后一项结尾**不可有逗号**（JSON 语法）。

## 加载行为总结

| 场景 | 行为 |
| --- | --- |
| 条目 `[0]` 为空串或 `"\"\""` | 跳过 |
| 条目不是数组 / 首元素非字符串 / 缺 `[1]` | 跳过并告警，不中断 |
| `[0]` 或 `[2]` 正则编译失败 | 触发异常 → **中止本文件处理并从 `.bak` 恢复** |
| `[2]` 全文匹配不到 / `#{n}` 残留 | 跳过该条并告警 |
| `select.replaceFile` 非 `main.js` / `renderer.js` | 整条跳过（invalidcheck 也不计数） |

# Mapping File Format (localization.json) (English)

[简体中文](#映射文件格式localizationjson) | **English**

`json/localization.json` is the project's **core data**: a mapping table of English source text → Chinese translations. The loader reads it to perform replacements, the auto-maintain tool inspects it, and CI validates it.

> The path `json/localization.json` is a public contract of the released program (the remote-pull URL points at it permanently); it **must not be moved**.

## Top-Level Structure

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `version` | int | recommended | JSON file-format version (currently `3`), bumped only on format changes |
| `minversion` | string | recommended | Minimum loader version required (e.g. `"1.0.0"`). If the loader is older, it prompts to upgrade / asks whether to force; a parse failure aborts outright |
| `tip` | string[] | no | Announcements shown at loader startup, printed one by one |
| `select` | object[] | yes | Entries the user is prompted to apply **selectively** during localization |
| `main` | array | yes | Mappings used to replace `main.js` (non-empty) |
| `main_dev` | array | no | Quick-replace mappings for `main.js` development and debugging (used with `--devreplace`) |
| `renderer` | array | yes | Mappings used to replace `renderer.js` (non-empty) |
| `renderer_dev` | array | no | Quick-replace mappings for `renderer.js` development and debugging |

Consequences of failed structural validation: `main` / `renderer` missing or empty, or `select` missing → the loader **exits with an error immediately**; it never replaces with incomplete data.

## Mapping Entry Format

Every element of `main` / `renderer` / `main_dev` / `renderer_dev` is a string array with **two** or **three** elements:

```json
["查找正则", "替换文本"]
["查找正则", "替换文本", "全局查找正则"]
```

| Element | Role | Description |
| --- | --- | --- |
| `[0]` | find regex | Compiled with `std::regex` (ECMAScript syntax) and applied to the whole file via `regex_replace`. Empty strings or `"\"\""` are skipped |
| `[1]` | replacement text | Used as the `regex_replace` format string: `$1`…`$9` reference `[0]`'s capture groups; `#{n}` placeholders are backfilled from the third element (see below). Backslashes are **literals** — never add them for regex escaping |
| `[2]` (optional) | global find regex | First searches the whole file for the **first** match, backfills its capture groups into `[1]`'s `#{1}`, `#{2}`… placeholders, then performs the main replacement |

### The `#{n}` Placeholder Backfill Mechanism

Used when the translation must embed dynamic text that only becomes known when the js runs. Order of operations:

1. Run `regex_search` with `[2]` over the whole file and take the **first** match;
2. Replace every `#{i}` in `[1]` with the text of capture group i (a `$` inside the backfilled value is escaped first to prevent accidental format-string expansion);
3. If any `#{digit}` placeholder **remains** unbackfilled in `[1]` → the whole entry is **skipped** (writing unbackfilled placeholders would break js syntax);
4. If `[2]` matches nothing in the file → the entry is skipped with a warning;
5. Once backfilling is done, `[0]` performs the regular replacement.

### Simple Examples

```json
["&File", "文件(&F)"],
["New &repository…", "新建存储库(&R)"]
```

```json
["&View\"", "视图(&V)\""]
```

> The find pattern deliberately includes the trailing quote to avoid false-matching longer text such as `&View on GitHub`.

### Example with a Capture Group (`$1`)

Bundled js variable names (like `yD`) often change between releases, so `..` fuzzy-matches them:

```json
["Ee\\.createElement\\((..),null,this.props.repositoryName",
 "Ee.createElement($1,null,this.props.repositoryName"]
```

- In JSON, `\\(` → actual regex `\(` → matches the literal `(`;
- The replacement text is inserted **literally**: `$1` references the find regex's first capture group; **the replacement must never contain `\\(`** — that is a literal backslash and would write `createElement\(` into the js, causing an immediate syntax error.

### Three-Element Example (`#{n}`)

A real example from `select` (force-enabling preview features):

```json
["===process\\.env\\.GITHUB_DESKTOP_PREVIEW_FEATURES\\}",
 "===/*process.env.GITHUB_DESKTOP_PREVIEW_FEATURES*/\"1\"}"]
```

## Structure of `select` Array Elements

| Field | Type | Description |
| --- | --- | --- |
| `replaceFile` | string | Target file; must **exactly equal** `main.js` or `renderer.js` (any other value makes the whole entry inert) |
| `tooltip` | string | The hint shown to the user at runtime |
| `enable` | bool | Whether this entry is enabled |
| `replace` | string[][] | Two-dimensional replacement array; each row follows the main-array entry format: `[find regex, replacement text, optional find regex]` |

Runtime behavior: entries with `enable: true` print their `tooltip` and ask the user (**default y**); once confirmed, all of the entry's replacement rows are applied. Typical uses: enabling preview features, experimental translations.

```json
{
    "replaceFile": "renderer.js",
    "tooltip": "是否强制开启预览版选项对应的功能",
    "enable": false,
    "replace": [
        ["===process\\.env\\.GITHUB_DESKTOP_PREVIEW_FEATURES\\}",
         "===/*process.env.GITHUB_DESKTOP_PREVIEW_FEATURES*/\"1\"}"]
    ]
}
```

## Entry Ordering Rules (Important)

Find patterns are **replaced one by one from the top; the first match wins** — earlier entries rewrite the text, and later entries match against the rewritten result. Therefore:

- New entries are generally **appended at the end**;
- If a new entry is **"short-in-long"** with an existing one (its find pattern is a substring of another's, e.g. `"Save"` vs `"Save":"Add"`), the more specific (longer) entry must be **inserted before** the broader (shorter) one — otherwise the broad entry matches first and the specific one is dead forever;
- The CI JSON quality check warns about mis-ordered "short-in-long" entries.

## Translation Style Conventions

The CI quality gate checks these (failure blocks the release):

- Questions consistently end with the **full-width** `？`;
- Translations **leave no** trailing spaces;
- Regex syntax must compile under `std::regex` (see the blacklist in the [Regular Expression Guide](正则表达式指南.md));
- `#{n}` placeholders and `$n` capture groups must be used legally;
- The last item of an array must **not** end with a comma (JSON syntax).

## Loading Behavior Summary

| Scenario | Behavior |
| --- | --- |
| Entry `[0]` is an empty string or `"\"\""` | Skipped |
| Entry is not an array / first element is not a string / `[1]` missing | Skipped with a warning, no abort |
| `[0]` or `[2]` fails regex compilation | Raises an exception → **aborts this file's processing and restores from `.bak`** |
| `[2]` finds no match in the file / `#{n}` placeholders remain | Entry skipped with a warning |
| `select.replaceFile` is neither `main.js` nor `renderer.js` | Whole entry skipped (not even counted by invalidcheck) |
