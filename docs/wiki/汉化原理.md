# 汉化原理

**简体中文** | [English](#how-the-localization-works-english)

本文面向想理解（或参与改进）加载器实现的读者，按主流程 `src/GitHubDesktop2Chinese.cpp` 的实际执行顺序讲解。

## 总体架构

```text
┌─────────────────────────┐     ┌──────────────────────────────┐
│ C++20 加载器 (src/)      │     │ 汉化映射 (json/localization.json)
│ 单文件 exe，无外部依赖    │────▶│ main / renderer / select / …  │
│ CLI11 + httplib + json   │     └──────────────────────────────┘
│ + spdlog + OpenSSL       │                ▲
└──────────┬──────────────┘                │ 每日自动维护
           │ 正则替换                        │
           ▼                                │
┌─────────────────────────┐     ┌──────────────────────────────┐
│ GitHub Desktop 资源目录  │     │ tools/auto-maintain (Node.js) │
│ main.js / renderer.js   │     │ 失效检测 + 未翻译候选提取      │
│ + .bak 备份             │     └──────────────────────────────┘
└─────────────────────────┘                ▲
                                           │ CI 驱动
                              ┌──────────────────────────────┐
                              │ .github/workflows（统一工作流）│
                              └──────────────────────────────┘
```

核心思路：**不改 GitHub Desktop 的安装器与更新机制**，只在每次更新后对其 `resources/app` 下的两个 js 文件做「查找 → 正则替换」。数据（映射）与逻辑（加载器）分离，GitHub Desktop 频繁更新时只需增量维护映射文件。

## 为什么选正则映射替换

GitHub Desktop 的 `main.js` / `renderer.js` 是打包压缩后的产物，变量名每个版本都会变（如 `yD`、`Ee.createElement`），但**面向用户的字符串字面量稳定得多**。因此：

- 直接按偏移/上下文硬编码 → 每个版本全部失效；
- 按字符串字面量精确匹配 → 大多数条目跨版本存活；
- 对易变片段用正则模糊匹配（如 `(..)` 匹配任意两位字符）→ 进一步提高存活率。

失效是可自动检测的：对每条映射的查找正则在最新 js 上做 `regex_search`，匹配不到即失效。这就是 `--invalidcheck` 与自动维护工具的共同原理。

## 启动阶段

### 跨平台入口与编码

- Windows 使用 `wmain` 宽字符入口：命令行参数在非 UTF-8 代码页（如中文 GBK）下无损转换，避免 CLI11 内部转换崩溃（v1.2.11 修复）；
- 控制台统一设为 UTF-8（`SetConsoleOutputCP(CP_UTF8)`）并启用 VT 转义序列（彩色输出）；
- 链接 `app.manifest` 声明进程级 UTF-8 主动代码页，窄字符路径在任何系统区域设置下都按 UTF-8 解释——中文路径不再乱码；
- Windows 注册窗口关闭事件回调：汉化中途关窗弹提示，避免半途而废。

### 版本与开发者模式

- `FILEVERSION` 宏由 CI 注入（如 `1.2.24`），本地构建默认 `0.0.0-Dev.0`；
- Dev 版行为差异：spdlog 输出级别开到 debug、**跳过自更新检查**、开发者菜单多出「手动指定程序版本」选项（用于调试 `minversion` 逻辑）；
- 按住 `Shift` 启动（`GetAsyncKeyState` 查询物理按键，避免无消息循环下 `GetKeyState` 的过期状态）或 `-d` 进入开发者菜单。

### 代理探测

优先级：环境变量 `HTTPS_PROXY` / `https_proxy`（`ParseProxyAddress` 统一解析：允许 `http(s)://` 前缀、`user:pass@` 认证段（当前忽略——调用侧暂不支持认证）、`[IPv6]:port` 形式；端口范围 1–65535，裸 IPv6 判无效）→ Windows 系统 IE 代理（`WinHttpGetIEProxyConfigForCurrentUser`，支持 `http=…;https=…` 多段形式取第一段）。POSIX 无系统代理时回退环境变量。环境变量解析失败会打印错误并返回空（继续走系统代理）。探测结果用于**全部**联网请求。

## 自更新机制

1. 请求 `api.github.com/repos/Tupig/GitHubDesktop2Chinese/releases/latest` 取 `tag_name` 与资产列表；
2. `FileVer < remoteVer` 时提示更新（**默认 n**），在资产中按名字精确找 `GitHubDesktop2Chinese.exe`（找不到再退而取第一个 `.exe`）；
3. 确认后用 `browser_download_url`（github.com 浏览器直链）下载：
   - **不消耗 API 配额**，避免共享 IP 触发匿名 60 次/小时限流的 403；
   - 按资产声明的 `digest`（`sha256:<hex>`）校验完整性，不符不替换；
   - **断点续传**：`.part.url` 旁证文件记录上次下载地址，跨版本续传（URL 不一致）时删除重下，防止拼出混合文件；错误响应不写入 `.part`，不污染续传；
   - 瞬时 403 / 连接失败自动重试；
4. 下载成功后程序立即退出，由更新流程完成自身替换，用户再次运行即可。

## 目录解析

优先级：`-g` 参数 → 注册表 → 交互输入。

| 来源 | 逻辑 |
| --- | --- |
| `-g` 参数 | 校验存在且含 `index.html`（`resources\app` 的标志文件），否则 CLI 校验错误退出 |
| Windows 注册表 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\GitHubDesktop` 读 `DisplayVersion` + `InstallLocation`，拼 `…\app-<版本>\resources\app` |
| 交互输入 | 循环要求输入目录，支持拖拽（自动剥首尾引号与空白，按 UTF-8 构造路径）；输入流结束（管道）时返回空并报错，避免死循环 |

顺带查询 `desktop/desktop` 的 `releases/latest`（仅正式版，`release-` 前缀剥离）与本地版本对比，落后时黄色提示「需更新」。用 `releases/latest` 而不是 tags 列表，避免把 `3.6.7-beta` 这类预览版误判为最新正式版（v1.2.21 修复）。

## 回滚短路（--rollback）

在映射加载**之前**执行——回滚只需要「目录 + 备份」，不应被断网或映射损坏阻断：

- `main.js.bak → main.js`、`renderer.js.bak → renderer.js` 独立执行，单文件失败计错误数；
- 还原走**原子化**路径：先写同目录临时文件，再 rename 覆盖目标，中途断电/失败不会留下半截文件；
- 目标存在时先删后拷；任一失败退出码 1，全部成功退出码 0。

## 映射加载与校验

```
-r 仅远程 ──▶ 拉 raw.githubusercontent.com/…/json/localization.json
否则 ──▶ 本地 localization.json 存在？──是──▶ 读本地
                        │否
                        ▼
                  拉远程（失败则退出）
```

解析成功后做**前置结构校验**，防止带着残缺数据做替换：

- 顶层必须是 JSON 对象；
- `main` / `renderer`（或 dev 模式下的 `main_dev` / `renderer_dev`）必须存在、为数组且非空；
- `select` 必须存在且为数组；
- `tip` 数组逐条打印为公告。

之后：

- `main.js` / `renderer.js` 缺失但有 `.bak` → 先从备份还原（自愈）；
- `.bak` 不存在 → 立即创建。**备份只在首次创建**，永远对应「最初未汉化」状态；
- `minversion` 校验：解析失败直接中止（带着未知兼容性替换更危险）；版本不足时交互询问输入 `f` 强制，`--nopause` 下跳过询问直接强制。

## 替换引擎

对 `main.js` 与 `renderer.js` 各跑一遍相同流程：

```
读入全文（--translationfrombak / --invalidcheck 时优先读 .bak）
for 每条映射:
    前置校验（数组、非空、首元素为字符串），畸形条目跳过并告警
    查找正则为空串或 "\"\"" → 跳过
    编译 item[0] 为正则
    ├─ invalidcheck 模式: regex_search 计数失效（含第三项），continue
    ├─ 无 item[1] → 跳过
    ├─ 有 item[2]（第三项查找正则）:
    │     全文首个匹配 → 捕获组 i 回填替换文本中的 #{i} 占位符
    │     ├─ 残留未回填的 #{n} → 跳过该条（防语法破坏）
    │     └─ 全文匹配不到 → 跳过该条并告警
    └─ regex_replace(全文, item[0], 替换文本)
写入（--noreplaceres / invalidcheck 时不写）
```

关键设计：

- **替换文本是 `std::regex_replace` 的 format 串**：`$1`、`$2` 等捕获组引用可用（详见[映射文件格式](映射文件格式.md)）；
- **第三项与 `$n` 是两套机制**：`$n` 来自 `item[0]` 自身的捕获组；`#{n}` 来自 `item[2]` 在**全文**首个匹配的捕获组，先回填再执行主替换。回填值中的 `$` 会被转义为 `$$`，防止被 format 串意外展开；
- **先匹配者生效**：替换按数组顺序从头到尾执行，前面的条目改写文本后，后面的条目在改写结果上匹配——「短含长」条目必须排在更宽泛条目之前（见[正则表达式指南](正则表达式指南.md)）；
- **异常即回滚**：`std::regex_error` 或其他异常会中止本文件处理，**不写半成品**，并自动从 `.bak` 恢复目标文件；
- **原子写入**：先写临时文件再替换目标，写入中断不损坏源文件。

## select 可选项

替换完常规数组后，遍历 `select`：

- `replaceFile` **精确等于** `main.js` / `renderer.js`（其他取值整条跳过——与 CI 质量校验的取值域检查一致）且 `enable: true` 才生效；
- 打印 `tooltip` 提示，用户确认（**默认 y**）后执行其 `replace` 二维数组，行格式与主数组一致（支持三元素）；
- 坏行（缺列 / 非字符串）跳过并告警，不中断整个 select 段。

## 错误检查模式（崩溃调试）

`--mainerrorcheck` / `--rendererrorcheck` 在替换循环内做「分批写入」：每替换一条打印日志，累计到用户指定条数写盘一次，用户可随时调整粒度逐步逼近写坏程序的那条映射。输入流结束时自动变为「全部替换完一次性写入」，管道运行不挂起。

## 收尾

- 请求贡献者 API 展示前 10 位贡献者（装饰性信息，失败不中断）；
- `PAUSE`：Windows 借 `cmd pause` 等任意键，POSIX 等一行回车（EOF 立即返回）；`--nopause` 跳过；
- 退出码：`--invalidcheck` 的失效计数（钳制到 255），其余场景 0 / 1 / 2 / 3 语义见[命令行参数](命令行参数.md)。

## 工具层

`src/utils/` 按职责拆分为五个子头，`utils.hpp` 为伞形入口：

| 头文件 | 职责 |
| --- | --- |
| `utils.hpp` | 伞形入口，聚合下列五个子头 |
| `encoding.hpp` | 宽窄字符串互转、路径构造（UTF-8 ↔ UTF-16） |
| `system.hpp` | 环境变量、HTTP/IE 代理探测 |
| `fs_io.hpp` | 文件读写（含原子写入） |
| `http.hpp` | HTTP 客户端、TLS 证书校验、自更新（SHA256 + 断点续传） |
| `input.hpp` | 交互输入（y/n 选择、布尔输入，含非交互兜底） |

版本号解析不在 `src/utils/` 内，位于 `src/version/Version.hpp`（自研三段版本号解析与比较）。

自研版本解析的原因：`std::regex` 处理版本字符串开销大且语义模糊，手写解析可精确控制 `v` 前缀、`-Dev` 后缀、非法输入等边界，并避免溢出风险。

# How the Localization Works (English)

[简体中文](#汉化原理) | **English**

This page is for readers who want to understand (or help improve) the loader implementation, following the actual execution order of the main flow in `src/GitHubDesktop2Chinese.cpp`.

## Overall Architecture

```text
┌─────────────────────────┐     ┌──────────────────────────────┐
│ C++20 加载器 (src/)      │     │ 汉化映射 (json/localization.json)
│ 单文件 exe，无外部依赖    │────▶│ main / renderer / select / …  │
│ CLI11 + httplib + json   │     └──────────────────────────────┘
│ + spdlog + OpenSSL       │                ▲
└──────────┬──────────────┘                │ 每日自动维护
           │ 正则替换                        │
           ▼                                │
┌─────────────────────────┐     ┌──────────────────────────────┐
│ GitHub Desktop 资源目录  │     │ tools/auto-maintain (Node.js) │
│ main.js / renderer.js   │     │ 失效检测 + 未翻译候选提取      │
│ + .bak 备份             │     └──────────────────────────────┘
└─────────────────────────┘                ▲
                                           │ CI 驱动
                              ┌──────────────────────────────┐
                              │ .github/workflows（统一工作流）│
                              └──────────────────────────────┘
```

Core idea: **do not touch GitHub Desktop's installer or update mechanism** — after each update, only perform "find → regex replacement" on the two js files under its `resources/app`. Data (the mapping) and logic (the loader) are separated, so frequent GitHub Desktop updates only require incremental mapping maintenance.

## Why Regex-Based Mapping Replacement

GitHub Desktop's `main.js` / `renderer.js` are bundled and minified artifacts; variable names change in every release (e.g. `yD`, `Ee.createElement`), but **user-facing string literals are far more stable**. Therefore:

- Hardcoding by offset/context → everything breaks every release;
- Exact string-literal matching → most entries survive across versions;
- Fuzzy regex matching for volatile fragments (e.g. `(..)` matching any two characters) → even higher survival rates.

Invalidation is automatically detectable: run `regex_search` for each mapping's find pattern against the latest js — no match means invalid. This is the shared principle behind `--invalidcheck` and the auto-maintain tool.

## Startup Phase

### Cross-platform entry and encoding

- Windows uses the `wmain` wide-character entry: command-line arguments are losslessly converted even under non-UTF-8 code pages (e.g. Chinese GBK), avoiding crashes in CLI11's internal conversion (fixed in v1.2.11);
- The console is set to UTF-8 (`SetConsoleOutputCP(CP_UTF8)`) with VT escape sequences enabled (colored output);
- Linking `app.manifest` declares a process-level UTF-8 active code page, so narrow-character paths are interpreted as UTF-8 under any system locale — no more garbled Chinese paths;
- Windows registers a window-close event callback: closing the window mid-localization pops a confirmation, preventing half-finished work.

### Version and developer mode

- The `FILEVERSION` macro is injected by CI (e.g. `1.2.24`); local builds default to `0.0.0-Dev.0`;
- Dev-build behavior differences: spdlog log level up to debug, **self-update check skipped**, and the developer menu gains a "set program version manually" option (for debugging `minversion` logic);
- Hold `Shift` at startup (`GetAsyncKeyState` polls the physical key, avoiding `GetKeyState`'s stale state without a message loop) or pass `-d` to enter the developer menu.

### Proxy detection

Priority: `HTTPS_PROXY` / `https_proxy` environment variables (`ParseProxyAddress` does unified parsing: `http(s)://` prefixes allowed; `user:pass@` credential segments (currently ignored — callers do not support authentication yet); `[IPv6]:port` form; port range 1–65535, bare IPv6 considered invalid) → the Windows system IE proxy (`WinHttpGetIEProxyConfigForCurrentUser`, supporting the `http=…;https=…` multi-segment form, taking the first segment). On POSIX, falls back to environment variables when there is no system proxy. A parse failure of the environment variable prints an error and returns empty (system proxy is still tried). The detected result is used for **all** network requests.

## Self-Update Mechanism

1. Requests `api.github.com/repos/Tupig/GitHubDesktop2Chinese/releases/latest` for `tag_name` and the asset list;
2. When `FileVer < remoteVer`, offers an update (**default n**), locating `GitHubDesktop2Chinese.exe` by exact name among the assets (falling back to the first `.exe` if absent);
3. Once confirmed, downloads via `browser_download_url` (a github.com browser direct link):
   - **Consumes no API quota**, avoiding 403s from the anonymous 60-requests/hour limit triggered by shared IPs;
   - Verifies integrity against the asset's declared `digest` (`sha256:<hex>`); a mismatch is never swapped in;
   - **Resumable download**: the `.part.url` sidecar file records the previous download URL; a cross-version resume (mismatched URL) deletes and restarts, preventing mixed files; error responses are never written into `.part`, keeping resume state clean;
   - Transient 403s / connection failures retry automatically;
4. After a successful download the program exits immediately so the update flow can replace it; the user simply runs it again.

## Directory Resolution

Priority: `-g` argument → registry → interactive input.

| Source | Logic |
| --- | --- |
| `-g` argument | Validates existence and the presence of `index.html` (the marker file of `resources\app`); otherwise exits with a CLI validation error |
| Windows registry | Reads `DisplayVersion` + `InstallLocation` from `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\GitHubDesktop` and joins `…\app-<version>\resources\app` |
| Interactive input | Loops prompting for the directory, supports drag-and-drop (strips surrounding quotes and whitespace automatically, builds the path as UTF-8); when the input stream ends (pipes), returns empty with an error instead of looping forever |

It also queries `desktop/desktop`'s `releases/latest` (stable releases only, `release-` prefix stripped) and compares with the local version, showing a yellow "update available" hint when behind. Using `releases/latest` rather than the tags list avoids mistaking pre-releases like `3.6.7-beta` for the latest stable (fixed in v1.2.21).

## Rollback Short-Circuit (--rollback)

Runs **before** mapping loading — rollback only needs "directory + backups" and must not be blocked by a dead network or a corrupted mapping:

- `main.js.bak → main.js` and `renderer.js.bak → renderer.js` run independently; a per-file failure counts as an error;
- Restoration uses an **atomic** path: write a temp file in the same directory first, then rename over the target — power loss or failure midway never leaves truncated files;
- An existing target is deleted before copying; exit code 1 if any step fails, 0 when all succeed.

## Mapping Loading and Validation

```
-r 仅远程 ──▶ 拉 raw.githubusercontent.com/…/json/localization.json
否则 ──▶ 本地 localization.json 存在？──是──▶ 读本地
                        │否
                        ▼
                  拉远程（失败则退出）
```

After a successful parse, an **upfront structural validation** runs to prevent replacing with incomplete data:

- The top level must be a JSON object;
- `main` / `renderer` (or `main_dev` / `renderer_dev` in dev mode) must exist, be arrays, and be non-empty;
- `select` must exist and be an array;
- Each `tip` array entry is printed as an announcement.

Afterwards:

- If `main.js` / `renderer.js` is missing but `.bak` exists → restore from the backup first (self-healing);
- If `.bak` does not exist → create it immediately. **Backups are created only once**, always reflecting the "originally unlocalized" state;
- `minversion` check: a parse failure aborts immediately (replacing with unknown compatibility is more dangerous); when the version is too low, interactive mode asks for `f` to force, and `--nopause` skips the prompt and forces directly.

## The Replacement Engine

The same flow runs once each for `main.js` and `renderer.js`:

```
读入全文（--translationfrombak / --invalidcheck 时优先读 .bak）
for 每条映射:
    前置校验（数组、非空、首元素为字符串），畸形条目跳过并告警
    查找正则为空串或 "\"\"" → 跳过
    编译 item[0] 为正则
    ├─ invalidcheck 模式: regex_search 计数失效（含第三项），continue
    ├─ 无 item[1] → 跳过
    ├─ 有 item[2]（第三项查找正则）:
    │     全文首个匹配 → 捕获组 i 回填替换文本中的 #{i} 占位符
    │     ├─ 残留未回填的 #{n} → 跳过该条（防语法破坏）
    │     └─ 全文匹配不到 → 跳过该条并告警
    └─ regex_replace(全文, item[0], 替换文本)
写入（--noreplaceres / invalidcheck 时不写）
```

Key design points:

- **The replacement text is a `std::regex_replace` format string**: capture-group references like `$1`, `$2` are available (see [Mapping File Format](映射文件格式.md) for details);
- **The third element and `$n` are two separate mechanisms**: `$n` comes from capture groups of `item[0]` itself; `#{n}` is backfilled from capture groups of the **first full-text match** of `item[2]`, before the main replacement runs. `$` inside backfilled values is escaped to `$$` to prevent accidental format-string expansion;
- **First match wins**: replacements run in array order from top to bottom; earlier entries rewrite the text that later entries then match against — "short-in-long" entries must precede the broader ones (see the [Regular Expression Guide](正则表达式指南.md));
- **Exception means rollback**: `std::regex_error` or any other exception aborts processing of the file, **never writes partial output**, and automatically restores the target from `.bak`;
- **Atomic writes**: write a temp file first, then swap it in — an interrupted write never corrupts the source file.

## The `select` Optional Items

After the regular arrays, `select` is iterated:

- An item only takes effect when `replaceFile` **exactly equals** `main.js` / `renderer.js` (any other value skips the whole item — consistent with the CI quality check's value-domain check) and `enable` is true;
- The `tooltip` is printed, and after user confirmation (**default y**) its `replace` two-dimensional array is applied, with the same row format as the main arrays (three-element rows supported);
- Bad rows (missing columns / non-strings) are skipped with a warning without aborting the whole select section.

## Error-Check Mode (Crash Debugging)

`--mainerrorcheck` / `--rendererrorcheck` performs "batched writes" inside the replacement loop: one log line per replacement, writing to disk after a user-specified number of entries, with the granularity adjustable at any time to close in on the mapping that breaks the program. When the input stream ends it automatically becomes "replace everything, write once", so piped runs never hang.

## Wrap-Up

- Queries the contributors API to show the top 10 contributors (decorative; failure does not abort);
- `PAUSE`: on Windows, borrows `cmd pause` to wait for any key; on POSIX, waits for one line of Enter (EOF returns immediately); `--nopause` skips it;
- Exit code: the invalid-entry count for `--invalidcheck` (clamped to 255); for other scenarios, the 0 / 1 / 2 / 3 semantics are documented in [Command-Line Options](命令行参数.md).

## The Utility Layer

`src/utils/` is split by responsibility into five sub-headers, with `utils.hpp` as the umbrella entry:

| Header | Responsibility |
| --- | --- |
| `utils.hpp` | Umbrella entry aggregating the five sub-headers below |
| `encoding.hpp` | Wide/narrow string conversion and path construction (UTF-8 ↔ UTF-16) |
| `system.hpp` | Environment variables, HTTP/IE proxy detection |
| `fs_io.hpp` | File I/O (including atomic writes) |
| `http.hpp` | HTTP client, TLS certificate verification, self-update (SHA256 + resumable download) |
| `input.hpp` | Interactive input (y/n choices, boolean input, with non-interactive fallbacks) |

Version-number parsing lives outside `src/utils/`, in `src/version/Version.hpp` (a hand-rolled three-part version parser and comparator).

Why a hand-rolled parser: `std::regex` is expensive and semantically fuzzy for version strings; handwritten parsing precisely controls the `v` prefix, the `-Dev` suffix, invalid input and other edge cases, and avoids overflow risks.
