# 维护操作备忘

收录维护过程中踩过并验证过的工具行为与操作规范，每条都来自真实事故（详见文末相关 issue）。能落地的方案一律落地在仓库里，本页只保留无法靠代码消除、但必须让维护者知道的部分。

## gh CLI 操作规范

### issue/PR 正文一律 `--body-file`

PowerShell 中 `gh issue create --body "..."` 内联正文一旦含反引号（Markdown 代码标记），参数就会被 PowerShell 解析破坏，导致**静默失败**或内容损坏——命令可能返回成功，但正文已残缺。

规范：正文一律先以 UTF-8 编码写入临时文件，再以 `--body-file` 传入。

### 拉取 job 日志遇转义序列

`gh api .../actions/jobs/<job-id>/logs` 拉取的日志含终端颜色码时，gh 会拦截并拒绝输出，需追加 `--allow-escape-sequences`。

### CI 失败排查顺序

1. `gh api repos/<repo>/commits/<sha>/check-runs` 列出全部 check-run
2. 逐 check-run 取 annotations——"Set up job" 类失败看注解比看步骤日志更直接
3. 最后取 job logs 细看

## 文件与行尾

### `.gitattributes` 已锁定 `eol=lf`

全部文本文件统一 LF 检出（Windows 含在内），`git add` 不应再出现 `LF will be replaced by CRLF` 类行尾告警；若再次出现说明 `.gitattributes` 被改动。静态库等二进制类型（`*.a`、`*.lib` 等）已显式声明 `binary`，禁止任何转换。

### 隐藏目录的文件搜索

对 `.github/` 等 dot 开头目录使用文件名通配（glob）搜索会返回空结果，造成"文件不存在"的误判。替代方式：用内容搜索（rg 直接搜内文），或 `Get-ChildItem -Recurse .github -Name` 列目录。

## 文档存放规范

- 交接文档、实施计划等**持久性产物**不得存放于配置了自动清理的目录；
- 自动清理方案必须显式维护排除清单（如 `handoff-*.md`）；
- 重要文档双写：主存位置 + 临时副本。

# Maintenance Notes

Verified tool behaviors and operating rules collected from real incidents (see the related issues at the end). Anything fixable in the repo is fixed in the repo; this page only keeps what cannot be eliminated by code but every maintainer must know.

## gh CLI rules

### Always use `--body-file` for issue/PR bodies

In PowerShell, `gh issue create --body "..."` breaks **silently** once the inline body contains backticks (Markdown code markers): the command may still succeed while the body is corrupted.

Rule: always write the body to a UTF-8 temp file first, then pass `--body-file`.

### Job logs with escape sequences

`gh api .../actions/jobs/<job-id>/logs` refuses to print logs containing terminal color codes unless you add `--allow-escape-sequences`.

### CI failure triage order

1. `gh api repos/<repo>/commits/<sha>/check-runs` to list all check-runs
2. Read annotations per check-run — for "Set up job" style failures, annotations beat step logs
3. Only then fetch the job logs for details

## Files and line endings

### `.gitattributes` locks `eol=lf`

All text files check out as LF (Windows included); `git add` should never emit `LF will be replaced by CRLF` warnings again. If it does, `.gitattributes` was modified. Binary types (`*.a`, `*.lib`, etc.) are explicitly declared `binary` and never converted.

### Searching hidden directories

Filename globbing over dot directories such as `.github/` returns empty results and leads to false "file missing" conclusions. Use content search (rg over the file contents) or `Get-ChildItem -Recurse .github -Name` instead.

## Document storage rules

- Persistent artifacts such as handoff documents and implementation plans must never live in auto-cleaned directories;
- Any auto-cleanup scheme must keep an explicit exclusion list (e.g. `handoff-*.md`);
- Write important documents twice: primary location + a temporary copy.
