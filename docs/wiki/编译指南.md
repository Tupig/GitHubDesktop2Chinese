# 编译指南

项目基于 **CMake ≥ 3.30 + C++20**，支持三套工具链：**MSVC（Windows）/ AppleClang（macOS）/ GCC（Linux）**。仅支持 **64 位**（x64 / arm64）构建，32 位会在 CMake 配置阶段直接 `FATAL_ERROR`。

```powershell
# 三平台通用
cmake -B build
cmake --build build --config Release
```

## 1. 环境准备

### Windows（MSVC + VS2022）

1. 安装 [Visual Studio 2022](https://visualstudio.microsoft.com/)，勾选「使用 C++ 的桌面开发」工作负载（含 CMake 组件与 Ninja）；
2. 无需预装 OpenSSL——CMake 会自动下载预编译 x64 静态库（见第 3 节）；
3. 无需额外装 vcpkg / conan：所有第三方头文件与库都随仓库提交在 `third_party/`。

**方式 A：VS2022 直接打开（推荐日常开发）**

1. 克隆仓库；
2. VS2022 → 「打开 → 本地文件夹」选择仓库根目录（VS 通过 CMakePresets.json 自动识别）；
3. 配置下拉框选 `x64-debug` 或 `x64-release` 预设（Ninja 生成器，产物在 `out/build/<预设名>/`）。

**方式 B：命令行**

```powershell
cmake --preset x64-release          # 配置（Ninja, cl.exe）
cmake --build --preset x64-release  # 构建
```

> 命令行方式需在「Developer PowerShell for VS 2022」中执行，保证 `cl.exe` 与 Ninja 在 PATH。

### macOS（AppleClang）

```bash
# 依赖：Xcode Command Line Tools + OpenSSL + CMake/Ninja
xcode-select --install
brew install openssl cmake ninja

cmake -B build -G Ninja
cmake --build build
```

CMake 通过 `find_package(OpenSSL)` 自动发现 Homebrew 的 OpenSSL。CI 发布的 macOS 产物**按架构拆分**（`GitHubDesktop2Chinese-macos-x64` / `-macos-arm64`）：基于上游 OpenSSL 源码构建静态库、静态链接，并以 strip + LTO 裁剪体积（部署目标 macOS 11.0）；本地构建默认只出当前架构的动态链接版本，功能等价。

### Linux（GCC）

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build libssl-dev

cmake -B build -G Ninja
cmake --build build
```

## 2. CMake 配置要点

| 要点 | 说明 |
| --- | --- |
| 版本宏 | CI 通过 `-DFILE_VERSION=…` 注入版本号；本地构建默认 `0.0.0-Dev.0` → 开发者版本（debug 日志、跳过自更新、可用 `--devsetver`） |
| 64 位守卫 | `CMAKE_SIZEOF_VOID_P != 8` 直接报错；对 VS `-A x64` 与 Ninja 两条路径都生效 |
| MSVC 选项 | `/utf-8`（中文字符集）；Debug `/bigobj`；Release `/Zi` + `/DEBUG`（生成 PDB） |
| 清单 | 链接 `src/app.manifest` 声明进程级 UTF-8 主动代码页——缺失时非中文系统上中文路径参数会解析失败 |
| C++ 标准 | `CXX_STANDARD 20`（用到 `std::optional`、`string::ends_with` 等） |

## 3. OpenSSL 依赖（平台差异）

| 平台 | 来源 | 备注 |
| --- | --- | --- |
| Windows | CMake 自动下载 `libssl.lib` / `libcrypto.lib` 到 `third_party/openssl/lib` | **SHA256 固定校验**，下载损坏自动删除报错；本地构建走 `ghproxy.cc` 镜像前缀，CI（`-DGitHubActions=ON`）走 GitHub 直链。下载失败时可手动用 curl 下载后放入该目录。源码目录只读时可用 `-DGHD2C_OPENSSL_ROOT=<可写目录>` 覆盖下载/查找/头文件/链接位置 |
| macOS / Linux | `find_package(OpenSSL REQUIRED)` | `brew install openssl` / `apt install libssl-dev` 后自动发现 |

第三方头文件库（CLI11、cpp-httplib、nlohmann/json、spdlog、WinReg）全部 header-only，随仓库提交于 `third_party/include/`，无获取步骤。

## 4. 产物

| 平台 | 产物 | 位置 |
| --- | --- | --- |
| Windows | `GitHubDesktop2Chinese.exe` | `out/build/x64-release/` 或 `build/` |
| macOS / Linux | `GitHubDesktop2Chinese` | `build/` |

> Windows 本地构建依赖系统 VC++ 运行库（Release 动态链接 CRT），与发布产物行为一致。

## 5. 常见构建错误

| 现象 | 原因与处理 |
| --- | --- |
| `仅支持 64 位架构（x64/arm64）构建` | 用了 32 位工具链/预设。VS 里选 x64 预设；命令行配置加 `-A x64` 或用 `x64-*` 预设 |
| `cl.exe` 找不到 | 未在 VS 开发者终端中运行命令行构建；或仅装了 VS Code 未装 MSVC |
| OpenSSL 下载失败 / 卡住 | 网络问题。手动下载 `libssl.lib` / `libcrypto.lib`（CMake 输出中含 URL）放入 `third_party/openssl/lib/` 后重新配置；下载超时默认 300 秒，可用 `-DDOWNLOAD_OPENSSL_TIMEOUT=600` 调大 |
| CMake 版本过低报 `cmake_minimum_required` | 升级 CMake ≥ 3.30 |
| macOS 找不到 OpenSSL | `brew install openssl` 后重跑；Homebrew 路径由 CMake 自动探测 |
| 中文注释编译报错（MSVC） | 已通过 `/utf-8` 处理；若自己新增编译选项勿移除该项 |

## 6. 构建后验证

```powershell
# 不写盘，仅批量检测映射有效性（退出码 0 = 全部有效）
./build/GitHubDesktop2Chinese.exe --nopause dev --invalidcheck --translationfrombak

# 或用 Node 工具做同等检测 + 未翻译候选提取
cd tools/auto-maintain && npm run all
```

改动加载器逻辑时，建议配合 `main_dev` / `renderer_dev` 数组 + `--devreplace` 快速验证，参见[贡献指南](贡献指南.md)。
